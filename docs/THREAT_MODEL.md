# Threat Model

> 版本 v0.1（2026-10-10）。本文是**工程口径**的威胁模型，与 [`SECURITY.md`](../SECURITY.md) 配套：`SECURITY.md` 讲漏洞上报与已知限制，本文讲**资产、对手与攻击面**。
> 本文件**不是**第三方审计结论，也不声称覆盖全部风险。

## 1. 资产（需要保护什么）

| 资产 | 位置 | 泄露后果 |
|---|---|---|
| 身份私钥 / 会话棘轮状态 | 应用数据目录（加密落盘），设备密钥由 DPAPI 保护 | 可解密历史与后续消息 |
| 混合预钥（hybrid pre-key） | 本地缓存 + 服务端发布的公钥 bundle | 私钥泄露 → 可代本端完成握手 |
| 访问令牌（`fk_token`） | 前端 `localStorage` | 可冒充本端调用 API（不含解密历史消息的能力） |
| 消息明文 | 仅存在于两端内存与本地存储 | 直接暴露通信内容 |

## 2. 对手模型

| 对手 | 能力 | 主要防线 |
|---|---|---|
| 网络窃听者 | 被动读取全部流量 | E2EE（X25519+ML-KEM-768）；填充/混淆仅抬高分析成本 |
| 网络主动攻击者 | 篡改、重放、注入 | 密钥协商的认证性、棘轮重放保护、会话指纹 |
| **服务端（半可信）** | 可读写数据库中继的消息与公开 bundle | 消息内容端到端加密；**但**服务端可影响 bundle 的新鲜度与分发（见 §4） |
| 同机其它进程 / 用户 | 读取本地文件与内存 | 会话落盘加密 + DPAPI；前端 token 存于 localStorage（弱于原生凭据存储） |
| WebView 内的 XSS | 在渲染层执行脚本 | CSP + `withGlobalTauri` 的 IPC 面；**注意**：CSP 仍含 `unsafe-inline` / `blob:` |

## 3. 攻击面与现状

| 面 | 现状 |
|---|---|
| WebView2 渲染层 | 最薄弱环节，漏洞不在本项目控制内 |
| IPC / Command Scope | 已收窄文件系统访问范围（待办：进一步收敛到 `$APPDATA`） |
| CSP | 存在 `unsafe-inline` 与 `blob:`（因仍有内联脚本），待清理 |
| 开发工具 | 需确认**发布构建**中 devtools 已关闭 |
| 服务端 bundle 分发 | 已修「陈旧 bundle」：新 hybrid 预钥生成后立即上传（PR #24） |
| 协议协商 | 已修「协议分叉」：复用守卫增加协议校验 + 握手指纹（`TEST-PROTOCOL.md` §七） |

## 4. 明确不在范围内 / 已知限制

- **未做第三方密码学审计**：CI / KAT / TVLA 是内部证据，不等于外部审计结论（见 `SECURITY.md`）；
- **`pqc_kyber` 0.7.1 的 KyberSlash**：仅存在于 WASM 实验层，不在生产密钥交换路径（见 `SECURITY.md` → Known Dependency Vulnerabilities）；
- **JS 侧大整数运算非常量时间**：纯 JS 路径的常量时间性未经验证，敏感运算应走 Rust 侧；
- **流量分析**：填充与混淆是「抬高成本」而非「消除」；
- **端点被完全控制**（键盘记录、调试器附加）不在防护范围内。

## 5. 变更纪律

改动**密码学路径、密钥存储、IPC 面或 CSP** 的 PR，请在描述中说明对本文的影响；必要时同步更新。
