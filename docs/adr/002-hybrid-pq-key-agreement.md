# ADR-002: 握手采用 X25519 + ML-KEM-768 混合

## Status
Accepted

## Context

两个动机同时存在：

1. **先存后解（harvest-now-decrypt-later）**：只靠 X25519 的会话，未来被量子计算机攻破后，今天录下的密文会被回溯解密；
2. **互操作性**：纯后量子方案在过渡期不一定能与所有对端协商成功。

## Decision

会话建立采用**混合密钥协商**：X25519（经典）+ ML-KEM-768（后量子），两路共享秘密合并后派生会话密钥。任一算法未被攻破，会话即安全。

## Consequences

- ➕ 同时获得经典与后量子的安全性（不是二选一）；
- ➕ 保留降级路径：对端不支持后量子时回落到经典握手；
- ➖ 握手报文更大（ML-KEM-768 的公钥与密文都比 X25519 大一个数量级）；
- ➖ **代价是状态复杂**：会话必须记录「本次协商用的是哪种协议」。我们确实在这上面栽过——复用守卫原先只判断「是不是 hybrid」，不比对本次握手指纹，导致两端协议分叉后永远协商不上。修法是复用条件里加上协议校验与握手指纹（见 `TEST-PROTOCOL.md` §七）；
- ➖ 对端公钥由服务端分发，因此**服务端发布的 bundle 必须新鲜**。陈旧 bundle 会造成「本端私钥是新生成的、对端却用旧公钥封装」→ 共享密钥不一致。现已改为：生成新的 hybrid 预钥后立即上传（PR #24）。

## Alternatives considered

- **只用 X25519**：过渡期简单，但放弃后量子目标；
- **只用量子安全算法**：互操作与性能代价都更高，且没有「至少经典这一层也安全」的冗余。
